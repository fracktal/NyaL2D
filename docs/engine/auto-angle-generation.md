# 각도별 모양 자동 생성 설계 (2026-11-03 결정)

## 결정

- **실행(런타임)은 2D 방식**: Live2D와 같이 각도별 2D 모양(키폼)을 저장하고 섞는다. 3D 렌더링은 하지 않는다.
- **만들 때(저작)는 3D를 활용**: 깊이 추정, 얼굴 템플릿, AI 생성 이미지 등으로 각도별 모양의 **초안을 자동으로** 만든다.
- 자동 결과는 언제나 **고칠 수 있는 키폼**으로 저장한다. 사람이든 AI든 "이 각도에서 코를 조금 더"처럼 다듬을 수 있어야 한다.
- 원본 그림의 픽셀은 그대로 쓴다. 자동 생성은 **꼭짓점을 어디로 옮길지**만 정한다. 그래서 그림체가 바뀌지 않는다.

배경 논의: [ai-authoring-research.md](ai-authoring-research.md), 이 스레드의 2D→3D→2D 논의(애니 그림은 각도마다 일부러 3D와 다르게 그려지므로 실행을 3D로 하면 그림체가 깨진다).

## 전체 흐름

```
그림 1장 또는 PSD
   │
   ├─(1) 부위 나누기 ─────── PSD가 있으면 그대로, 없으면 See-through류로 자동 분해
   ├─(2) 깊이·특징점 ─────── 레이어별 깊이(Marigold/Depth Anything류), 얼굴 특징점(눈·코·입·윤곽)
   ├─(3) 대리 3D 만들기 ──── 레이어마다 깊이로 부조(얕은 입체 판)를 만들고, 얼굴은 템플릿 형상에 맞춤
   ├─(4) 돌려서 투영 ─────── 대리 3D를 목표 각도(예: 좌우 ±30°, 상하 ±20°)로 돌린 뒤 2D로 다시 찍음
   │                         → 각 메시/워프 격자 꼭짓점의 새 위치 = 그 각도의 키폼 초안
   ├─(5) 애니 보정 ───────── 태그별 규칙으로 "3D답지 않게" 고침 (아래 표)
   ├─(6) 확인·다듬기 ─────── 각도별로 렌더 → 비전 AI가 이상한 곳을 지적 → 자동/대화로 수정
   ▼
키폼(엔진 형식)으로 저장 → 엔진이 실시간으로 섞어서 재생
```

## 단계별 방법

### (1) 부위 나누기
- PSD가 있으면 레이어를 그대로 쓴다(지금 앱의 PSD 가져오기와 같은 출발점).
- 레이어 없는 그림은 See-through(Apache-2.0)로 약 23개 부위 + 가려진 부분 채우기. 무거운 GPU 모델이라 브라우저 밖 "생성 서버"에서 돈다.

### (2) 깊이와 특징점
- **레이어 단위 앞뒤 깊이**: 자동 추출 값을 그대로 신뢰한다. 앞머리 > 얼굴 > 뒷머리 같은 순서와 대략적 거리.
- **얼굴 특징점**: 눈·코·입·턱선 위치. 대리 3D 얼굴을 맞추는 기준.
- 얼굴 안의 미세한 굴곡(코 높이, 볼 곡률)은 사진용 깊이 모델이 애니에서 틀리기 쉬우므로, 추정값 대신 (3)의 템플릿 형상을 우선한다.

### (3) 대리 3D
- 완전한 3D 모델을 만들지 않는다. 목적은 "돌렸을 때 각 꼭짓점이 대략 어디로 가나"를 계산하는 것뿐이다.
- 일반 레이어: 레이어 깊이 + 가장자리로 갈수록 뒤로 휘는 얕은 곡면(부조). 앞머리는 얼굴 곡면을 따라 띄운 판.
- 얼굴: 애니풍 얼굴 템플릿 형상(둥근 머리 + 낮은 코)을 특징점에 맞춰 늘린다. 템플릿은 몇 종(갸름/둥근/치비) 준비.
- 머리 회전 중심(목 위)과 몸 회전 중심(허리)은 특징점과 부위 태그로 추정.

### (4) 돌려서 다시 2D로
- 목표 각도 격자: 기본은 `angleX`(좌우) × `angleY`(상하) 각 3키 = 9개 조합. 몸통 `bodyAngleX`는 따로.
- 각 꼭짓점을 대리 3D 위에 올려 돌리고, 원근 없는(또는 약한) 투영으로 2D 위치를 구한다.
- 결과를 **얼굴 각도 워프 디포머의 격자 키폼**으로 저장하는 것이 기본. 레이어마다 다른 깊이 덕분에 앞머리가 얼굴보다 더 많이 움직이는 시차가 자동으로 생긴다.

### (5) 애니 보정 규칙 (초기안)

| 부위 태그 | 3D 그대로라면 | 애니답게 보정 |
| --- | --- | --- |
| `eye.*` | 먼 쪽 눈이 크게 납작해짐 | 납작해지는 정도를 줄임(예: 50%), 눈 모양 유지 |
| `nose` | 정면에서도 높이가 있어 위치가 크게 이동 | 정면에선 거의 고정, 옆으로 갈수록 이동 과장 |
| `mouth` | 먼 쪽이 줄어듦 | 줄어듦 완화, 중심 이동만 |
| `face.outline` | 볼선이 그대로 회전 | 먼 쪽 볼선을 안으로 당겨 실루엣 유지 |
| `hair.front` | 얼굴과 같이 회전 | 시차 강조(더 많이 이동) + 물리 연결 |
| `hair.back` | 가려지며 반대로 이동 | 반대 방향 이동, 가장자리 노출은 See-through 채우기 사용 |
| `ear.*` | 먼 쪽은 사라짐 | 불투명도 키폼으로 서서히 숨김 |

규칙은 데이터(설정 파일)로 두고, 모델마다 세기를 조절할 수 있게 한다. 처음엔 손으로 정하고, 나중에 예시 모델을 모아 값을 다듬는다.

### (6) 확인과 다듬기 (우리 프로젝트의 차별점)
- 각 각도 조합을 헤드리스로 렌더해 한 장의 비교표로 만든다.
- 비전 AI가 "왼쪽 30도에서 앞머리와 이마 사이가 벌어짐" 같은 문제를 찾고, 해당 키폼을 고치는 편집 명령을 제안·실행한다.
- 사용자는 대화로 "옆모습에서 코 좀 더 뾰족하게"처럼 요청할 수 있다.
- 기존 연구들(Bunraku, CartoonAlive 등)은 한 번 생성으로 끝나므로, 이 반복 루프가 우리만의 강점이 된다.

### (선택) AI 생성 각도 이미지 활용
- 이미지 생성 AI로 "옆 30도 모습"을 그리게 한 뒤, 그 **픽셀은 쓰지 않고** 원본과의 대응점(광학 흐름)만 구해 꼭짓점 이동 방향의 참고로 쓴다.
- 대리 3D가 놓치는 애니식 왜곡을 데이터로 배울 수 있는 길이다. 생성 품질에 좌우되므로 2차 목표로 둔다.

## 엔진(형식)에 필요한 것

| 항목 | 이유 | 반영 |
| --- | --- | --- |
| 레이어 깊이, (선택) 꼭짓점별 깊이 | 대리 3D 재계산, 나중에 실시간 시차 옵션 | 형식 v0에 선택 필드로 |
| 의미 태그 (`eye.left`, `hair.front` …) | 보정 규칙과 AI 편집이 같은 이름을 씀 | 형식 v0 |
| 2축 격자 키폼 (`angleX`×`angleY`) | 자동 생성 결과의 기본 그릇 | 2단계 |
| 블렌드 셰이프(가산) | Bunraku류 예측 결과, 보정값을 덧붙이기 | 5단계 → **3단계로 앞당김** |
| 생성 출처 표시 (`generatedBy`, 손으로 고쳤는지) | 다시 생성할 때 사람이 고친 부분을 덮어쓰지 않기 | 형식 v0 |
| 부분 갱신 API | 다듬기 루프가 빠르게 돌도록 | 2단계 |

## 구현 순서

1. **최소판 (엔진 2단계 직후)**: 손으로 나눈 PSD + 레이어 깊이를 손으로 입력 → 부조 대리 3D → 좌우 3키 키폼 생성. 보정 규칙 없이 시차만. 효과를 눈으로 확인.
2. **얼굴 템플릿 + 보정 규칙**: 특징점 맞춤, 위 표의 규칙, 상하 각도 추가.
3. **자동 깊이·자동 분해 연결**: 깊이 모델과 See-through를 생성 서버로 연결.
4. **비전 AI 다듬기 루프**: 헤드리스 렌더(엔진 6단계)와 연결.
5. **(선택) 생성 이미지 대응점 활용**.

## 위험과 미확인

- 애니 얼굴 특징점 검출기와 깊이 모델이 실제 애니 그림에서 얼마나 정확한지는 아직 직접 시험하지 않았다. 3단계 전에 샘플 그림 10~20장으로 측정한다.
- 생성 서버용 모델들의 **가중치 라이선스**는 코드 라이선스와 다를 수 있어 각각 확인해야 한다.
- 큰 각도(±45° 이상)와 손·소품이 얼굴을 가리는 그림은 초기 범위에서 제외한다.
