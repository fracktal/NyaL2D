# 단계별 로드맵

기간은 AI가 주로 코드를 쓰고 사람이 방향과 품질을 보는 지금 방식 기준의 대략적 추정이다. 실제 속도를 보고 2단계 끝에 다시 잡는다.
각 단계는 **눈으로 확인할 수 있는 결과물**로 끝나도록 나눴다.

| 단계 | 내용 | 끝났을 때 볼 수 있는 것 | 대략 |
| --- | --- | --- | --- |
| **0. 기초** | 형식 명세 v0, 좌표계·단위 규칙, 저장소 구성, Rust↔웹 빌드, 자동 테스트 틀 | 빈 뷰어가 뜨고, 테스트가 자동으로 돈다 | 1~2주 |
| **1. 그리기** | 텍스처 메시 로드·표시, 그리기 순서, 불투명도, 사전 곱셈 알파, WebGL2 렌더러 | 잘라 놓은 캐릭터 그림이 깨끗하게 조립되어 보인다 | 1~2주 |
| **2. 움직이기** | 파라미터, 다중 축 키폼 보간, 워프(쌍선형)·회전 디포머, 자유 중첩 | 슬라이더로 고개를 돌리고 눈을 감긴다 | 3~4주 |
| **3. 다듬기** | 마스크(중첩·반전), 블렌드 모드, 곱하기/스크린 색, 파라미터별 그리기 순서, 컬링, 블렌드 셰이프(5단계에서 앞당김) | 눈동자가 흰자 안에서만 움직이고, 볼이 붉어진다 | 2~3주 |
| **4. 살아있게** | 진자 물리, 자동 깜빡임·숨쉬기, 모션 재생, 표정, 시선 추적, 립싱크 | 가만히 둬도 숨쉬고 머리카락이 흔들린다 | 3~4주 |
| **5. 고급 변형** | 베지어 워프, 글루, 뼈대 스키닝 | 손으로 공들인 모델 수준의 매끄러운 각도 변화 | 4~6주 |
| **6. 성능·플랫폼** | WebGPU 경로, 헤드리스 렌더(이미지 출력), 바이너리 형식, 성능 측정 | 여러 캐릭터 동시 표시, 서버에서 스크린샷 | 2~4주 |
| **7. 저작 연결** | PSD → 메시 자동 생성, Iki 모델 변환기, AI용 조회·편집 API, 기존 편집 앱을 새 엔진으로 교체 | 지금 앱이 새 엔진 위에서 다시 동작 | 4~6주 |
| **8. 1.0** | 형식 고정, 마이그레이션 보장, 문서, 데스크톱/게임 엔진 런타임 검토 | 외부에 내놓을 수 있는 엔진 | 상황에 따라 |

## 병행 트랙: 각도별 모양 자동 생성

2026-11-03 결정에 따라, 엔진 2단계가 끝나면 [auto-angle-generation.md](auto-angle-generation.md)의 자동 생성기를 엔진과 나란히 만든다.

| 순서 | 내용 | 엔진 쪽 전제 |
| --- | --- | --- |
| A1 최소판 | PSD + 손으로 넣은 레이어 깊이 → 좌우 각도 키폼 자동 생성 | 2단계 |
| A2 얼굴 템플릿·애니 보정 | 특징점 맞춤, 태그별 보정 규칙, 상하 각도 | 3단계(블렌드 셰이프) |
| A3 자동 깊이·자동 분해 | 깊이 모델, See-through를 생성 서버로 연결 | - |
| A4 비전 AI 다듬기 루프 | 각도별 렌더 → AI가 문제 지적·수정 | 6단계(헤드리스 렌더) |

합계로 보면 2단계(움직이는 첫 모델)까지 약 1.5~2개월, 4단계(살아 움직이는 캐릭터)까지 약 3~4개월, 편집 앱 복귀(7단계)까지 약 6~8개월이다.

## 단계마다 지킬 것

- 새 기능은 적합성 테스트 모델과 함께 들어간다.
- 형식이 바뀌면 명세와 JSON Schema를 같은 변경에서 고친다.
- 단계가 끝날 때마다 뷰어 스크린샷을 남긴다.

## 바로 다음 할 일 (0단계)

1. 형식 명세 v0 초안 (`engine/spec/`): 파라미터, 노드 트리, 키폼, 메시까지.
2. Rust 코어 뼈대와 WASM 빌드, 최소 뷰어.
3. 테스트용 모델 2~3개를 손으로 작성 (사각형 하나, 워프에 든 사각형, 회전 중첩).

이 단계를 시작할 때 두 가지를 정하면 된다: `architecture.md` 2절의 언어 선택(추천: Rust 코어), 그리고 기존 `app/`을 저장소에 그대로 둘지 별도 폴더로 보관할지(추천: 그대로 두고 손대지 않음).
