# Live2D 대비 Iki에 부족한 것

Live2D Cubism(Editor + SDK)의 일반적인 기능을 기준으로, Iki(format 0.2.1 / engine 0.3.4 / editor 0.12.1)에 무엇이 더 있어야 그 수준에 가는지 정리한다.
근거: Iki `ROADMAP.md`, `packages/format/src/{types,validate}.ts`, 이 저장소의 `known-limitations.md`, NyaL2D에서 PSD 자동 리깅을 붙여 본 경험.

"어디서 해결?" 열의 뜻:
- **앱**: NyaL2D 안에서 파라미터를 구동하는 드라이버나 가져오기 단계로 만들 수 있다. 포맷·엔진 변경 없음.
- **에디터**: `@ikijs/editor`에 명령(EditCommand)이나 생성기를 추가해야 한다.
- **포맷+엔진**: `.iki` 스키마와 렌더러를 바꿔야 한다. 업스트림 기여나 포크가 필요하다.

## 1. 변형(리깅) 표현력: Live2D 수준의 핵심

| Live2D 기능 | Iki 현황 | 필요한 것 | 어디서 |
| --- | --- | --- | --- |
| 아무 오브젝트에 파라미터 2~3개 조합 키폼 (예: AngleX×AngleY×표정) | 워프 디포머 1개에 그리드 워프 1개만. 다중 드라이버 합성은 validate가 거부함 (`warps supports at most one grid warp`). `warp2d`로 AngleX×Y 조합 하나는 됨 | 다중 파라미터 키폼 블렌딩 (가산 합성 또는 N차원 격자) | 포맷+엔진 |
| 디포머 자유 중첩 (워프 안의 워프, 워프 아래 회전) | 중첩 워프, 워프 아래 행렬 계층 미지원 (ROADMAP 4d Deferred) | 디포머 계층 일반화 | 포맷+엔진 |
| 베지어 워프 (부드러운 곡면 변형) | 쌍선형 격자만 | 베지어/바이큐빅 패치 | 엔진 |
| 글루 (메시끼리 붙이기), 패스 디포머 | 없음 | 정점 결합 제약 | 포맷+엔진 |
| 아트메시 편집 (수동/자동 메시 분할, 정점 추가·삭제) | 토폴로지 편집 없음 (ROADMAP 5c Deferred). 자동 리깅이 만든 격자 메시만 있음 | 메시 생성·편집 명령 | 에디터 |
| 블렌드 셰이프 (Cubism 5, 가산 변형) | 없음 | 가산 정점 오프셋 | 포맷+엔진 |
| 파트별 키폼에 불투명도·그리기 순서·곱하기/스크린 색 | 불투명도 바인딩은 있음. 그리기 순서는 고정(`order`), 곱하기/스크린 색 없음 | 파라미터별 draw order, multiply/screen color | 포맷+엔진 |
| 블렌드 모드 (곱하기, 더하기 등) | 없음 (일반 합성만) | 셰이더 블렌드 모드 | 포맷+엔진 |
| 클리핑 마스크 여러 겹, 반전 마스크 | 한 단계, 반전 없음 | 중첩·반전 클리핑 | 포맷+엔진 |
| 컬링, 양면 표시 설정 | 없음 | 아트메시 컬링 플래그 | 포맷+엔진 |

## 2. 물리

| Live2D 기능 | Iki 현황 | 필요한 것 | 어디서 |
| --- | --- | --- | --- |
| 진자 물리 (입력 여러 개 → 출력 여러 개, 정규화, 진자 길이·흔들림 설정) | 스프링 리그(`physics`), 다관절 체인(`physicsChains`) 있음. 체인 편집 명령 없음 (5g Deferred) | 체인 편집, 워프 연동 체인 (7 Deferred) | 에디터 / 엔진 |
| 물리 자동 생성 | 자동 리깅이 `hair_front`에만 흔들림 리그를 만듦 | 옷·리본·꼬리 등 임의 파트용 자동 리그 | 에디터 |

## 3. 애니메이션과 상호작용: 대부분 앱에서 가능

| Live2D 기능 | Iki 현황 | 필요한 것 | 어디서 |
| --- | --- | --- | --- |
| 모션 (motion3: 커브, 베지어/계단 보간, 루프, 페이드, 우선순위) | 모션 파일·키프레임 재생 없음. 내장 Idle만 | 모션 포맷 + 플레이어 + 페이드/우선순위 관리 | 앱 (나중에 포맷) |
| 표정 (exp3: 파라미터 가산/곱/덮어쓰기 묶음) | 없음 | 표정 프리셋과 블렌딩 | 앱 |
| 포즈 (pose3: 팔 A/B처럼 파트 그룹 전환) | 없음. 불투명도 바인딩으로 흉내 가능 | 파트 전환 그룹 | 앱 (+가져오기) |
| 립싱크 (오디오 음량 → 입), MotionSync (음소 → 입 모양) | 없음 | 오디오 분석 → ParamMouthOpenY/Form | 앱 |
| 시선 추적 (마우스/카메라 따라 보기) | 없음. Idle이 고개 파라미터를 계속 덮어씀 | Look-at 드라이버, Idle과의 우선순위 | 앱 |
| 자동 눈 깜빡임, 숨쉬기 | Idle에 있음. 타이밍·진폭 고정 (`IdleMotionOptions`는 `rng`만) | 설정 가능한 Idle | 엔진 (작음) |
| 히트 영역, 사용자 데이터 | 없음 | 영역 정의 + 판정 | 포맷 / 앱 |

## 4. 저작 도구와 생태계

| Live2D 기능 | Iki 현황 | 필요한 것 |
| --- | --- | --- |
| 키폼을 캔버스에서 끌어서 만들기 (모든 디포머·메시) | 1D 격자 키폼만 드래그 저작. 자동 리깅 모델이 쓰는 2D 격자는 드래그 불가 (5d Deferred) | 2D·다중 파라미터 키폼 편집 UI, 타임라인 |
| 템플릿 적용, 표정 자동 생성 | 자동 리깅이 고정 프로파일 하나 (Live2D 샘플에서 잰 기본 리그) | 리그 템플릿 여러 종, 몸·팔 리그 |
| 형식 호환 (.moc3, model3.json) | 못 엶 | 가져오기/내보내기. moc3는 비공개 바이너리라 난이도 높음 |
| 플랫폼 SDK (Unity, 네이티브, 웹) | 웹(WebGL2)만. 변형은 CPU 계산 | GPU 변형, WebGPU, 다른 런타임 |
| 형식 안정성 | 0.x, 스키마가 예고 없이 바뀔 수 있음 | 1.0 고정 |

## 그 수준까지 가려면: 단계 제안

1. **앱에서 바로 할 수 있는 것** (포맷 변경 없음, NyaL2D에서 진행)
   - PSD 표정 변형을 파라미터에 연결: 閉じ目는 눈 감기에, 입 모양은 입 벌리기에 불투명도로 전환. Live2D 포즈·표정의 대체.
   - 모션 플레이어(간단한 키프레임 JSON), 표정 프리셋, 립싱크(마이크 음량), 시선 추적.
   - 위 기능을 에이전트 도구로도 노출해서 자연어로 "웃는 표정 만들어줘", "이 대사에 맞춰 말해줘"가 되게 하기.
2. **에디터 확장** (`@ikijs/editor`에 명령 추가, 업스트림 PR 후보)
   - 파트 정점 키폼·2D 격자 키폼 수정 명령, 메시 생성·편집, 물리 체인 편집, 자동 리깅에 몸·팔·소품 리그 추가.
3. **포맷+엔진 확장** (가장 큰 일, 업스트림과 설계 합의 필요)
   - 다중 파라미터 키폼 합성 → 디포머 중첩 → 블렌드 모드·곱하기/스크린 색 → 파라미터별 그리기 순서 → 중첩·반전 클리핑 → 글루·베지어 워프.
   - 이것이 Live2D 수준 표현력의 본체다. 1번과 2번만으로는 "자동 리깅된 상반신 VTuber 모델" 수준까지는 가지만, 손으로 공들인 Live2D 모델의 섬세한 각도 변화와 표정 변형은 3번 없이는 안 된다.
